## What it measures

The `foqa` directives that no longer serve, once every other selected rule
has run on the file, as ruff's `RUF100` does for `# noqa`. Each directive
gets at most one diagnostic, which lists its identifiers by reason:

- `unused`: a code of a directive (`# foqa:CODES` or `# furryp: foqa:CODES`)
  that suppressed no diagnostic, including `FUR000` and `FUR001`, which
  cannot be suppressed;
- `non-enabled`: a code of a rule that is not selected for the file
  (`select`, `ignore`, `per-file-ignores`);
- `duplicated`: a rule already named in the same directive, by its code or
  by its name.

A blanket `# foqa` that suppressed nothing is reported on its own. When a file
directive and a line directive cover the same diagnostic, the file directive
suppresses it and the line directive is reported. A blanket `# furryp: foqa`
exempts its whole file from this rule, so it is never reported, even once it no
longer serves: check it by hand. All of this as ruff does. An
identifier that names no rule is ignored, as ruff ignores the codes it does
not know: it suppresses nothing, and is only reported when it is repeated.

## Why it matters

A directive that no longer serves hides the next violation of the same rule
on that line, or in that file. Removing the directive as soon as the
violation is gone keeps the frozen debt honest.

## How to fix it well

- Run `furryp check --fix`. As ruff does for `RUF100`, it rewrites each
  reported directive with the codes that served (`# foqa:FUR101`), and
  removes the directive once it is empty: another comment on the line is
  kept, and a line left empty is deleted. Codes of rules that are not
  selected are removed too: fix with the full selection.
- By hand: remove the unused codes from the directive, and the directive
  itself once it is empty.
- Keep each code once per directive.
- Check `non-enabled` codes with the full selection before removing them:
  they may still serve when their rule runs.
- When a directive seems to have no effect, check its codes with
  `furryp rule --all`: a mistyped code is ignored. A malformed directive
  (`# foqa.`, `# foqa:FUR101;`) suppresses nothing and gets a warning on
  stderr, and only the first directive of a comment counts.

## What not to do

- Adding the code somewhere else, or making the code worse, so that the
  directive serves again.
- Replacing the codes with a blanket `# foqa`, which hides every rule.

## Example

The module was split and is now short: the file directive no longer
suppresses anything.

Flagged:

```python
# furryp: foqa:FUR102
"""Pricing helpers."""


def total(price: float, quantity: int) -> float:
    return price * quantity
```

Fixed:

```python
"""Pricing helpers."""


def total(price: float, quantity: int) -> float:
    return price * quantity
```
