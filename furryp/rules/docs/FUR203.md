## What it measures

How hard a function is to follow: an adaptation to Python of the cognitive
complexity of SonarSource (G. Ann Campbell). The score starts at 0, and so
does the nesting level `N`.

- +1 + `N`: `if`, ternary, `match` (once, not per `case`), `for`, `while`,
  each `except`.
- +1: `elif`, `else`, each sequence of identical boolean operators, each
  `case` guard, each `if` of a comprehension, and a function that calls itself
  directly (once).
- +1, only if the statement receives no other increment: `try`, `finally`,
  `with`, `break`, `continue`, `return`, `assert`, `pass`, `:=`. So
  `return total` gives +1, but `return a and b` gives only the boolean sequence.
- `N` + 1 for their content: the bodies of `if`, `elif`, `else`, loops, `except`
  and `case`, the operands of a ternary, `lambda`, nested functions and classes.
  `try` and `with` do not increase it.
- Nothing else counts: `raise`, `yield`, `await`, assignments, calls, the
  annotations of a signature…

A nested function or a `lambda` has no increment of its own: its content counts
in its parent, and it is not evaluated alone.

The diagnostic points at the name of the function, written with its qualified
name (`Parser.load`, `outer.inner`).

## Why it matters

Every nested branch adds to what a reader must keep in mind. A function with a
high score is hard to change without breaking one of its paths, and hard to
test: it often hides several functions.

## How to fix it well

- Look at the function as a whole: nesting costs the most.
- Replace nesting with early returns and guard clauses.
- Extract nested branches into well-named functions, and name long conditions.

## What not to do

- Moving the same nesting to a function called only once, with no meaning of
  its own.
- Replacing `if` statements with deeply chained boolean operators or
  ternaries: the logic is the same, and harder to read.

## Example

With `max` lowered to 5 to keep the example short:

```json
{"rules": {"cognitive-complexity": {"max": 5}}}
```

Flagged (score 8: `for` 1, `if` 2, `if` 3, `return` 1, `return` 1):

```python
def first_paid(orders):
    for order in orders:
        if order.closed:
            if order.paid:
                return order
    return None
```

Fixed (score 5: `for` 1, `if` 2, `return` 1, `return` 1; the condition has a
name):

```python
def is_paid(order):
    return order.closed and order.paid


def first_paid(orders):
    for order in orders:
        if is_paid(order):
            return order
    return None
```
