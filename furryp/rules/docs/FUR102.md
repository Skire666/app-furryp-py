## What it measures

The total number of physical lines of the file, everything included: code,
comments, blank lines and docstrings. Lines end with
`\r\n`, `\r` or `\n` only.

The diagnostic points at the first line beyond the limit.

## Why it matters

A very long module mixes several responsibilities: it is hard to navigate,
to review and to test, and every change touches a file that many others
depend on.

## How to fix it well

- Split the module along its responsibilities.
- Move each group of related functions or classes to its own module, and
  keep the names that other modules import.

## What not to do

- Removing blank lines, comments or docstrings to get under the limit.
- Joining several statements on one line.
- Splitting the module into arbitrary parts (`part1.py`, `part2.py`) that
  have no meaning of their own.

## Example

With `max-lines` lowered to 8 to keep the example short:

```json
{"rules": {"file-too-long": {"max-lines": 8}}}
```

Flagged (`geometry.py`, 11 lines):

```python
"""Geometry helpers."""

import math


def circle_area(radius: float) -> float:
    return math.pi * radius**2


def square_area(side: float) -> float:
    return side**2
```

Fixed (`geometry/circle.py`; `square_area` moved to `geometry/square.py`):

```python
"""Circle helpers."""

import math


def circle_area(radius: float) -> float:
    return math.pi * radius**2
```
