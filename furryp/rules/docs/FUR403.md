## What it measures

How far an expression reaches through other objects: the number of `.attr` of a
chain. `a.b.c.d.do()` has a depth of 4.

- A subscript is crossed without counting: `a.b[0].c` has a depth of 2.
- A call ends the chain: `a.b().c.d` gives two chains, `a.b` (1) and `().c.d`
  (2). With `count-calls`, the call is crossed: one chain of depth 3.
- With a root in `ignore-roots`, the first attribute does not count:
  `self.repo.session.query()` has a depth of 2.
- With `ignore-imported-modules`, a chain whose root is bound by `import x` or
  `import x as y` is ignored, such as `os.path.join`. A name bound by `from x
  import y` is an object like any other.

A chain gets one diagnostic, on its whole expression. It ends on its last
`.attr`: the call or the subscript that follows it is not part of it.

## Why it matters

A long chain ties the code to the structure of every object it goes through
(the Law of Demeter). When one of them changes, all these chains break, far from
the change, and each test must build the whole path.

## How to fix it well

- Ask the first object of the chain: add a method to it that does the work
  (`order.city()`), instead of walking through what it holds.
- Pass the object that is really needed as an argument.

## What not to do

- Splitting the chain into intermediate variables: the coupling is the same,
  and the chain is only harder to see.
- Adding a getter per level: the code still walks the same structure.

## Example

Flagged (depth 4):

```python
def city_name(order):
    return order.customer.address.city.upper()
```

Fixed (depth 1; the order knows how to reach its city):

```python
def city_name(order):
    return order.city_name()
```
