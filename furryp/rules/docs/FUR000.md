## What it measures

Whether furryp can check the file at all. The rule reports a path that does
not exist or cannot be read, bytes that cannot be decoded (the file is not
UTF-8 and does not declare its encoding), and code that does not tokenize or
parse with Python 3.14.

When the code does not parse, only the purely textual rules still run on the
file (`file-too-long`): every other check is skipped.
This rule is always active.

## Why it matters

A file that does not parse cannot be measured: a syntax error hides every
other violation of the file. A mistyped path in a CI job must fail the job
instead of passing silently.

## How to fix it well

- Fix the syntax error at the reported position; the message is the one of
  the Python parser.
- Save the file as UTF-8, or declare its real encoding on its first or
  second line: `# -*- coding: latin-1 -*-`.
- For `Failed to read file`, check the path given on the command line and the
  permissions of the file.

## What not to do

- Excluding the file from the analysis to make the error disappear: the file
  stays broken, and its other violations stay hidden.
- Keeping code that only parses with an older version of Python.

## Example

Flagged:

```python
def greet(name: str) -> str
    return f"Hello, {name}!"
```

Fixed:

```python
def greet(name: str) -> str:
    return f"Hello, {name}!"
```
