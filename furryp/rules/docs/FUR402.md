## What it measures

The imports of a file against the contracts of the project. Three types exist:

- `forbidden`: no module of `source` imports a module of `forbidden`.
- `layers`: from the highest layer to the lowest, a module never imports a layer
  above its own. A sublist is one level, without constraint between its
  elements, and modules outside of the layers are free. A module matched by
  several patterns belongs to the layer of the most specific one (more segments,
  then fewer `*`).
- `independence`: none of `modules` imports another.

A file has the name of its path relative to the first of `source-roots` that
holds it (`pkg/__init__.py` is `pkg`). The rule does not apply to a file outside
of them, and does nothing without a contract. Put the most specific root first.

Every import counts, at any depth of the file; relative imports are resolved
from the package of the module. A pattern `a.b` matches `a.b` and what is below
it, but not `a.bc`, and `*` stands for exactly one segment. With a `*`, each
module it matches counts apart: `independence` on `app.*` keeps `app.billing`
and `app.shipping` apart, and the messages cite these concrete names.

`from a.b import c, d` is reported once, on the statement, if a pattern matches
`a.b`; a pattern that only matches `a.b.c` is reported on `c`, as for
`import a.b.c`.

Layers are not strict: a module may import every layer below its own. To forbid
a precise dependency, such as the view of an MVP that must not reach the model,
write it as `forbidden` (`"source": ["app.view"], "forbidden": ["app.model"]`).

The rule covers what an import says directly. An indirect dependency (the view
goes through a module that imports the model), a name re-exported by a package
or `importlib` are not followed: these are choices that the developer assumes.

## Why it matters

Contracts keep the architecture from eroding one import at a time. A low layer
that imports a high one can no longer be tested, reused or changed alone, and a
single such import is enough to create a cycle between packages.

## How to fix it well

- Invert the dependency: declare an interface in the lower layer, and implement
  it in the higher one.
- Move the code that both sides need to a module they may both import.
- Pass the object as an argument instead of importing what creates it.

## What not to do

- Importing inside a function, or through `importlib`, to hide the import: the
  dependency is still there, and only harder to see.
- Removing a module from a contract so that it no longer applies to it.

## Example

The file of this example is the module `example`:

```json
{"rules": {"layer-violation": {"contracts": [{"type": "forbidden", "name": "no-http", "source": ["example"], "forbidden": ["requests"]}]}}}
```

Flagged:

```python
import requests


def latest_version(url):
    return requests.get(url, timeout=5).text
```

Fixed (the caller provides the function that fetches):

```python
def latest_version(fetch, url):
    return fetch(url)
```
