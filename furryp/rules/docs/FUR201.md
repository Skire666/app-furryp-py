## What it measures

The Halstead metric of the whole file, computed on its tokens: `volume` by
default, or `difficulty`, `effort` or `bugs` with the `metric` option. It is
counted on every token of the file: it is not the sum of its functions.

- Operators: `OP` tokens and hard keywords. Operands: other names (soft
  keywords such as `match` included), numbers, strings and the text of
  f-strings and t-strings.
- Not counted: comments, line breaks, indentation, docstrings, the quotes of
  f-strings and t-strings, and closing delimiters (a pair counts once).
- `n1`, `n2`: distinct operators and operands. `N1`, `N2`: their totals.
  `volume = (N1 + N2) × log2(n1 + n2)`,
  `difficulty = (n1 / 2) × (N2 / n2)`, `effort = difficulty × volume`,
  `bugs = volume / 3000`.

The diagnostic applies to the whole file, so it has no excerpt.

## Why it matters

The volume measures how much a reader must take in. A file with a very
high volume holds too much for one module, whatever its number of lines.

## How to fix it well

- Move the functions that go together to a module of their own, along a
  responsibility of the file.
- Remove duplication: the same logic written twice counts twice.
- Replace repeated module-level code with data and a single loop.

## What not to do

- Shortening variable names: the length of a name is not counted.
- Reusing one variable for several purposes: the code gets harder to read.
- Hiding logic in strings evaluated at run time.

## Example

With `max` lowered to 40 to keep the example short:

```json
{"rules": {"halstead-file": {"max": 40}}}
```

Flagged (`shapes.py`, volume 89.6):

```python
def area(width, height):
    return width * height


def perimeter(width, height):
    return 2 * (width + height)
```

Fixed (`shapes.py`; `perimeter` moved to `outline.py`, volume 34.9):

```python
def area(width, height):
    return width * height
```
