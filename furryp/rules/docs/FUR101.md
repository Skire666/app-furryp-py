## What it measures

The lines of code of a function, from the line of its first statement to its
end. A line of code holds at least one significant token: the signature, the
decorators, comments, blank lines and the docstring do not count. A function
written on one line (`def f(): return 1`) counts 1.

Every function is measured, methods included. The lines of a nested function
count in its parent, and the nested function is also evaluated alone.

The diagnostic points at the name of the function, written with its qualified
name (`Parser.load`, `outer.inner`).

## Why it matters

A long function does several things: it is hard to read in one go, to name
and to test, and each change risks breaking one of its other steps.

## How to fix it well

- Look at the function as a whole: what are its steps?
- Extract a step that does one thing and needs few variables from around it into
  a well-named function.

## What not to do

- Joining several statements on one line.
- Removing comments or blank lines: they are not counted.
- Splitting the function into `_part1` and `_part2` with no meaning of their
  own.

## Example

With `max-lines` lowered to 3 to keep the example short:

```json
{"rules": {"function-too-long": {"max-lines": 3}}}
```

Flagged (5 lines of code: docstring, comment and blank line excluded):

```python
def f(x):
    """Doc."""
    # comment
    y = x + 1

    z = call(
        y,
    )
    return z
```

Fixed (the step that computes the argument has its own name):

```python
def next_value(x):
    return x + 1


def f(x):
    """Doc."""
    return call(next_value(x))
```
